# 阶段 0 观察笔记（对照答案）

本次实测：DeepSeek `deepseek-chat`。

## 实验 1：temperature

实测：
- temperature=0 → 不重复答案 **2/5**（几乎同一句：先检索外部知识再生成）
- temperature=0.8 → 不重复答案 **5/5**（措辞全在飘：有的强调检索，有的强调时效）

结论：
- 0 = 更稳，适合抽 JSON、调工具、RAG 带引用。
- 0.8 = 更花，适合写文案；做工程会让评测抖动、格式翻车。
- 温度不是「更聪明」，只是采样更随机。

## 实验 2：上下文

实测：关键句在开头 / 中间 / 结尾，三次都答出 **7492**。
本次文本只有约 2200 字，对大模型太短，所以还没丢。

结论：
- 上下文有硬上限，超了会 `context_length_exceeded`。
- 更阴的问题是「lost in the middle」：书很长时，中间那段经常看不见。
- 所以不能把整本书塞进 prompt，必须切块 + 检索（这就是 RAG 存在的原因）。

## 实验 3：幻觉

实测：
- 「打印机在几楼」→ 引用原文：3 楼茶水间旁。
- 「年假多少天」→ **资料未提及，不能确定。** 没有编法定年假。

结论：
- 约束写清楚（必须引用、没有就拒答、禁止常识补全）能压住很多胡编。
- RAG 能减幻觉：先给证据，再让模型在证据里说话。
- 但不能消灭幻觉：检索可能漏、文档可能脏、模型仍可能无视约束。工程上还要评测、引用编号、低温度、拒绝回答。
