# 手写留痕（日常A 的存档）

## 为什么要有这个文件夹

日常A 每天只花 20 分钟，**但它是最容易变成"做了个寂寞"的一件事**——
因为手写练习如果只有一张打卡表的勾，三个月后你手上什么也没有，
既证明不了进步，也找不出自己反复卡在哪。

所以规矩是：**每天一个文件，文件名就是日期。**

三个月后你翻回 `2026-10-09.py`，会看到自己当时写得有多烂。
**那是唯一能证明你在进步的实物。** 别人夸你十句不如你自己翻回去看一眼。

## 规则（不许商量）

1. **20 分钟，计时器。** 到点就停，写不完照样提交——**"到点停"本身是训练的一部分**，
   因为面试也是限时的。
2. **AI 全关。** 包括那个对话、Copilot/Cursor 的生成式补全、属性自动补全。
   语法红线可以留，它不替你写。
3. **卡住就在注释里写"我卡在哪"。** 那句注释比写对的代码更值钱——
   它是你下次复习的入口。**不许因为卡住就去问 AI。**
4. **不许从仓库里其他文件复制。** 这条是 2026-10-09 加上的，见下面那件事。
5. 写完 `git add -A && git commit`。**没有 commit 的一天等于没发生。**

## 2026-10-09：为什么会多出第 4 条

那天的题是"写一个按 status 过滤工单的函数"，而 `learning/fde/stage0/server.py`
的第 43–46 行正好就是这个函数。

结果交上来的是 server.py 的逐字复制（连 `list(_DB.values())` 这层包装和变量名都一样）。

**这不是态度问题，是测量问题。** 那个练习的目的是量出"读得懂"和"写得出"之间的距离，
复制让这个距离量不出来——练习白做了。

于是第 4 条规则诞生，**同时诞生了这个文件夹**：
既然手写的产物必须能证明它不是你抄的，那就给它一个和仓库其他文件**长得不一样的题**。

> 读得懂代码不是本事，那本来就是你的强项。
> **从零写出来才是你标了"第一瓶颈"的那件事。**

## 命名

```
learning/handwrite/2026-10-09.py
learning/handwrite/2026-10-10.py
...
```

文件头写清：日期、题目、约束、以及"我卡在哪"。

## 不许做的事

- 不许把参考答案贴进去（参考可以放在**别的**文件里，或者干脆不存）
- 不许事后美化自己的代码再提交——那等于伪造体检报告
- 不许跳过"到点停"，把 20 分钟拖成 90 分钟——手写练的是**在压力下产出**，不是练出完美
