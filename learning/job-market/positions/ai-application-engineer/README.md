## 4. 三条 JD 原文（当"需求说明书"用，写代码时对照）

### ① 华中师范大学 —— 完整版（你的对标线）
> 熟练 Python + 至少一种框架；大模型技术栈 **RAG / Prompt Engineering / Agent 多智能体编排 / 模型微调(LoRA/SFT) 至少两项**；Web 后端 FastAPI/Flask/Spring Boot 或前端 React/Vue；Linux + Docker + CI/CD；MySQL/PostgreSQL + 向量库 Milvus/Chroma 优先；技术文档能力；CET-6 优先；**"驾驭 AI 工具的能力"**

**对照你的现状**：Python 🟡 / RAG ✅ / Prompt ✅ / Agent ✅ / 多智能体编排 ❌ / 微调 ❌ / FastAPI ❌ / Linux 🟡 / Docker ❌ / CI/CD ❌ / 向量库 🟡 / 文档 🟡
→ **"至少两项"你已满足两项（RAG + Agent）**，这就是你的底气。但服务化那半段是空的。

### ② 思迹信息（苏州工业园区）—— 最接近"真实工作内容"
> 负责 AI 应用及 AI Agent 设计/开发/测试/上线/持续优化；大模型与**飞书、北森**及现有业务系统接口集成（数据获取、AI 分析、结果回写、流程联动）；快速完成 **PoC/MVP**，推动智能评审/知识库/数据分析/流程自动化；设计**人机协同、人工审核、权限控制**机制；负责接口安全、运行监控、技术文档

**这条 JD 直接告诉你作品该长什么样**：不是一个"问答 demo"，而是"**能读写业务系统 + 有人工审核环节 + 有权限控制 + 能持续迭代**"的东西。
→ 你的第一个作品（窗口一 D23–D28 已排"内部知识库问答 + 工单 Agent"）**方向是对的**，但要加两样：**人工审核节点** + **权限角色**。

### ③ 德赛西威（南京）—— 评测要求写得最细
> 参与 AI 应用测试运维与效果评估、搭建**应用层评测体系 / 安全沙盒 / 权限管控**

**这条是你的隐藏优势**：你的 stage2 有注入测试 + 评测脚本，stage3 有评测集，stage5 有消融表。
合起来就是"应用层评测体系"的雏形——**7/11 家提到评测，但你已经在做了，只是没包装。**
