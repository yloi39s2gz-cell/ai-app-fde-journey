## 1. 窗口一（10-04 → 11-02）：本岗位**不加新任务**

**理由**：FDE 的技术及格线（40 分里的 25 分）需要 FastAPI + Docker + 云 + 公网作品。
这些东西**窗口一本来就在做**（START_HERE D5/D6/D23–D28），不需要为 FDE 加戏。

> **纪律**：这一栏故意留空。看到留空不要焦虑——这是刻意设计的，防止你 30 天内同时开三条战线。

唯一的动作（10 分钟）：**现在回答一个问题——出差 25–50% 你能不能接受？**
写进 [../../fde/FDE-拿offer学习计划.md](../../fde/FDE-拿offer学习计划.md) 的开头。
如果答案是"不能"，那么本岗位从 P0 降到"观察"，把时间全部给 AI 应用工程师。
（这个决定必须在 30 天内做，不要拖到投递时才发现。）

## 2. 窗口二（→ 2027-01）：技术 70% / 沟通 30%

### 2.1 技术（继续走主计划，此处只列 FDE 特有增量）

| # | 任务 | 产出 | 验收 |
| --- | --- | --- | --- |
| F-T1 | **选型论证**：用 stage1 的成本记账，对同一个任务做三条路线的对比（纯提示工程 / RAG / 微调） | 一张"成本 × 延迟 × 质量"三角表 | 面试官问"为什么用 RAG 不用微调"你能当场答 |
| F-T2 | **生产级代码**：pytest + GitHub Actions + 结构化日志（JSON logs） | 绿色 CI badge + 一份日志样例 | 崩溃时能从日志还原调用链 |
| F-T3 | **一次故障复盘**：部署后刻意制造故障（改错环境变量 / 打满超时），记录排查过程 | 一份复盘报告（现象→假设→验证→根因→防复发） | 报告里每一步都有命令和输出 |
| F-T4 | **数据管道最小版**：从 CSV/表格拉数据 → 清洗 → 入库 → 供 RAG 使用 | 一张 ETL 流程图 + 处理条数 | 能说出"脏数据在哪一步被拦掉" |

### 2.2 沟通（新增，占 30%）

| # | 任务 | 产出 | 验收 |
| --- | --- | --- | --- |
| F-C1 | **需求收敛练习**：拿一个模糊需求（"让我们客服效率高一点"），写 1 页方案 | 场景 / 边界 / 里程碑 / **明确不做的三件事** | 一页文档，读完能直接开工 |
| F-C2 | **诊断清单**：整理 15 个"见客户必问的问题" | 一份可复用问卷 | 覆盖：现状 / 数据在哪 / 谁用 / 成功标准 / **失败标准** |
| F-C3 | **去术语化**：把 stage5 的检索消融结果改写成非技术人能听懂的一段话 | 200 字、零术语 | 讲给一个不懂 AI 的人，他能复述 |
| F-C4 | **说不练习**：写 3 个"应该拒绝的需求"及话术 | 3 段话术 | 每段都给出"拒绝 + 替代方案" |

## 3. 窗口三（→ 2027-06）：技术 40% / 沟通 35% / 商业 25%（复刻白皮书配比）

| # | 任务 | 产出 | 验收 |
| --- | --- | --- | --- |
| F-B1 | **ROI 表**：给作品算账——替代多少人工小时 / 年省多少 / 建设成本多久回本 | 一张 ROI 表 | 三个数字能当场口算 |
| F-B2 | **成本核算**：算"每天 1 万次调用月成本多少" | 一个具体数字 | **面试会当场问，必须张口就来** |
| F-B3 | **企业部署流程**：读 2 篇企业 AI 落地复盘，画 POC→试点→推广 流程 | 一页流程图 | 能说出每个阶段客户最怕什么 |
| F-B4 | **竞争定位**：写"自研 vs Dify vs 外包"的对比论证 | 一段论证 | 能回答"为什么不直接用现成平台" |
| F-C5 | **模拟驻场**：我扮演客户给你提模糊需求（含情绪、含矛盾需求、含预算限制），你做一轮完整演练 | 一次 40 分钟的完整演练 | 你出方案 + 报价 + 说"这个做不了" |
| F-C6 | **工作坊**：设计 60 分钟"AI 入门工作坊" | 一份大纲 + 3 个演示 | 能让非技术人上手用一次 |
