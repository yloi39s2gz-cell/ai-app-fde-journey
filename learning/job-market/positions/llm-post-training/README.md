## 1. 一句话画像

**让模型本身变得更好、跑得更快。**
- **后训练（Post-training）**：SFT / LoRA / DPO / RLHF —— 让基座模型学会听话
- **推理优化**：量化、KV Cache、算子融合、vLLM/TensorRT-LLM —— 让同一个模型跑得更快更便宜

## 3. 为什么是 P3（诚实评估）

| 门槛 | 你的现状 | 能否绕过 |
| --- | --- | --- |
| 学历：硕士起步（多数岗） | ⚠️ | ❌ 部分公司可绕 |
| 算法基础：深度学习理论、Transformer 内部机制 | ❌ | 🟡 能补，但要 3–6 个月 |
| 分布式训练 / CUDA / GPU 集群 | ❌ | ❌ 需要真实算力环境（你本机没有 GPU） |
| 论文或有影响力的开源 | ❌ | ❌ |
| 推理优化：vLLM / 量化 / 算子 | ❌ | 🟡 部分能自学，但**没有 GPU 就只能读文档** |

**核心障碍：没有 GPU。** 这一条决定了这个方向在你现有条件下**无法通过"做出来"来学**，只能"读出来"——而面试官要的是做出来。

## 4. 唯一值得做的事（0.5 天，窗口二）

不做这个方向，但有**两件小事必须知道**，因为它们会在别的岗位面试中被问到：

| # | 任务 | 为什么 | 产出 |
| --- | --- | --- | --- |
| PT-1 | **搞清"什么时候该微调，什么时候该 RAG，什么时候该只改 prompt"** | AI 应用工程师 / FDE / AI PM **三个岗位都会问**。答案框架：数据变化频率、知识量、风格对齐需求、成本 | 一页决策树 |
| PT-2 | **搞清量化的基本分类**（INT8 / INT4 / GPTQ / AWQ）和"为什么量化能省显存" | 推理成本是 FDE 面试的"成本-延迟-质量"三角之一 | 一段 200 字解释 |

**就这两件。不做 LoRA 实操，不碰 CUDA，不学分布式训练。**

> 理由：LoRA 实操需要 GPU（成本高），而它对你目标的边际收益低于同等时间投入在 LangGraph/服务化上。
